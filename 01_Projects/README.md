# 项目目录使用规范

`01_Projects` 保存有独立目标、工作计划和交付物的研究与开发项目。一个项目一个目录，以 `README.md` 作为入口。本文约定项目组织方式，协作规则以适用的 `AGENTS.md` 为准。

## 核心规范

1. **稳定命名**：目录使用简短、清晰的项目名称，如 `fluProfiler-human`；避免空格和特殊字符。建立引用后尽量保持名称稳定。
2. **入口明确**：项目 `README.md` 说明研究问题、目标、范围、当前状态、预期交付物和关键资料入口。未确定的内容明确标为待确认。
3. **计划集中维护**：`tasks.md` 记录当前任务、完成条件和阻塞项；完成任务保留必要结果链接，不重复维护多份任务清单。
4. **记录重要依据**：`decisions.md` 按日期记录重要研究结论、方案选择及其依据。区分已验证事实、研究假设与待验证判断，不记录每次工具调用或低价值过程。
5. **目录按需创建**：有实际内容时再创建 `docs/`、`src/`、`notebooks/`、`data/`、`results/` 等目录，不要求每个项目使用完整模板。
6. **资料避免重复**：论文原文和阅读笔记保存在 `03_Literature`，共享数据、模型和素材优先保存在 `05_Resources`；项目使用相对链接引用。项目专属数据与中间结果可留在项目目录。
7. **结果可追溯**：数据记录来源、版本及必要的使用限制；分析结果记录输入数据、代码版本、运行参数和环境信息。原始数据与处理结果分开存放，不覆盖原始资料。
8. **保留历史**：关键版本保留可识别的历史；被替代内容和已完成项目归档至 `99_Archive`，归档时同步修正链接。项目完成前整理结论、交付物和未解决问题。

## 最小结构

```text
01_Projects/
├── README.md
└── fluProfiler-human/
    ├── README.md       # 项目定位、状态和入口
    ├── tasks.md        # 当前计划与完成条件
    └── decisions.md    # 重要结论与决策依据
```

代码、数据和结果较多时，可按需增加：

| 目录 | 用途 |
|---|---|
| `docs/` | 项目专属设计、研究方案与报告 |
| `src/` | 可复用的项目代码 |
| `notebooks/` | 探索性分析 |
| `data/` | 项目专属数据；按需区分 `raw/` 与 `processed/` |
| `results/` | 分析结果、图表与运行记录 |
